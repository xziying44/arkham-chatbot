# DIY 卡牌图片生成

你可以用 `arkham-cli` 工具，根据用户描述的卡牌信息生成阿卡姆恐怖LCG风格的卡牌图片，然后发送给用户。

## 何时使用

用户表达以下意图之一时触发：
- 想要制作/生成/设计一张卡牌（「帮我做张卡」「来张卡」「设计卡牌」「生成卡图」）
- 想要一张自定义的阿卡姆恐怖卡牌
- 描述了卡牌效果、名称、职业，希望看到成品

不要在用户只是讨论卡牌规则、询问游戏玩法时触发——只有当用户明确想「生成一张卡牌图片」时才用。

## 卡牌描述规范（重要！）

生成卡牌时，**必须使用规范的阿卡姆恐怖术语和图标语法**。这套卡牌渲染引擎使用的是 **emoji 符号 + 方括号【】语法**，不是尖括号标签。以下是核心规范，完整参考见同目录 `tag-reference.md`。

### 图标写法（直接用 emoji）

| 含义 | 写法 | 说明 |
|---|---|---|
| 意志 | 🧠 | 脑 |
| 智力 | 📚 | 书 |
| 战力 | 👊 | 拳 |
| 敏捷 | 🦶 | 脚 |
| 狂野 | ❓ | 任意属性 |
| 启动/行动 | ➡️ | 行动前缀 |
| 反应/快速 | ⚡ | 自由触发 |
| 回合结束 | ⭕ | after 类时点 |
| 守护者 | 🛡️ | 职阶 |
| 探求者 | 🔍 | |
| 流浪者 | 🚶 | |
| 潜修者 | 🧘 | |
| 生存者 | 🏕️ | |
| 独特 | 🏅 | 传奇卡 |
| 祝福 | 🌟 | 混乱袋标记 |
| 诅咒 | 🌑 | 混乱袋标记 |

### 关键术语（必须用规范词）

- **攻击行动**：写 `【攻击】`（方括号包裹动作名）
- **调查行动**：写 `【调查】`
- **谈判行动**：写 `【谈判】`
- **属性加成**：写 `得到+2👊`（直接用 emoji，不写 `<拳>`）
- **造成伤害**：写 `造成1点伤害`、`造成+1伤害`（不写「扣血」）
- **受到恐惧**：写 `受到1点恐惧`
- **弃置**：写 `弃掉`（动词，如「将其弃掉」），弃牌堆写 `弃牌堆`（不写「丢弃」）
- **横置/重整**：写 `横置`（exhaust）、`重整`（ready）（**不写「消耗」**，本游戏用「横置」）
- **获取资源**：写 `获得2资源`、`花费1资源`
- **发现线索**：写 `发现你所在地点的1个线索`
- **快速**：首行写 `快速。`
- **永久**：首行写 `永久。`
- **卓越**：首行写 `卓越。`
- **限制次数**：`(每回合仅限一次)`、`(每轮仅限一次)` 用圆括号
- **特性引用**：`{武器}`、`{精英}` 用花括号（渲染为特性图标）

## 工作流（严格按顺序）

### Step 1：收集卡牌信息

确认用户想要什么卡。必须收集：
- **卡牌类型**（见下方「卡牌类型参考」）。若用户没指定，默认推荐「升级卡」（最灵活的DIY卡）。
- **名称**（name）：卡牌标题。
- **正文**（body）：卡牌的效果描述，**必须用上面的规范术语和图标写**。把用户的大白话翻译成规范语法是你的核心工作。
- **职业**（class）：守护者/探求者/流浪者/潜修者/生存者/中立。
- **特性**（traits，可选）：JSON 数组，如 `["道具","工具","武器"]`。
- **费用**（cost，可选）：数字，支援卡/事件卡有费用，技能卡/升级卡一般不填。

若用户已给全这些信息，直接进入 Step 2。若信息不足，**简短地**问一句缺什么。

### Step 2：写 .card 文件

用 write 工具把卡牌定义写成 JSON 文件。**关键规则**：
- 文件名必须是 `NNN<任意>.card`，其中 NNN 是 3 位数字。一张卡用 `000.card`。
- 写到 `cards/in/` 目录下（先确保目录存在）。路径相对于你的工作目录。

支援卡模板（最常用）：

```json
{
  "type": "支援卡",
  "name": "卡牌名称",
  "class": "生存者",
  "cost": 3,
  "level": 0,
  "traits": ["道具", "工具", "武器"],
  "slots": "手部",
  "health": -1,
  "horror": -1,
  "body": "➡️：【攻击】。你本次检定得到+1👊。如果本次攻击成功，造成+1伤害。",
  "language": "zh"
}
```

升级卡/DIY卡模板（最灵活，只有标题+正文+职业）：

```json
{
  "type": "升级卡",
  "name": "卡牌名称",
  "class": "守护者",
  "body": "这里是卡牌效果正文，用规范术语和 emoji 图标写。",
  "language": "zh"
}
```

**字段说明**：
- `type`：卡牌类型（支援卡/事件卡/技能卡/升级卡/敌人卡/诡计卡/地点卡/故事卡/调查员）。
- `name`：标题。
- `body`：效果正文。**必须用 emoji + 【】规范语法**。
- `class`：职业（守护者/探求者/流浪者/潜修者/生存者/中立）。
- `traits`：特性 JSON 数组（**不带句号**），如 `["道具","武器","近战"]`。常见值：道具、武器、近战、枪械、工具、科学、法术、才能、仪式、遗物、乐器、守护、祝福。
- `cost`：费用数字（支援卡/事件卡填正数；技能卡/永久卡填 -1）。
- `level`：等级数字（0-5），默认 0。
- `slots`：槽位（支援卡用），如 `手部`、`法术`、`身体`、`盟友`、`附件`。无槽位填 `null`。
- `health`/`horror`：支援卡非盟友类填 -1；盟友类填正数。
- `language`：`zh`（默认）。

### Step 3：渲染卡图

用 bash 工具执行：

```bash
mkdir -p cards/out
.arkham/bin/arkham-cli render \
  --corpus cards/in \
  --assets .arkham/assets \
  --out cards/out
```

- 渲染耗时约 1-3 秒。
- 输出文件：`cards/out/000.png`（文件名 = .card 文件的前 3 位数字）。
- 看输出里的 `[OK ]` / `[ERR]` 行判断成功与否。若 `[ERR]`，看错误信息修正 JSON 后重试。
- JSON 语法错误是最常见的失败原因——写完后可以先用 `cat cards/in/000.card` 检查。
- `.arkham/` 目录是只读挂载的（arkham-cli 二进制和资产），不要尝试修改它。

### Step 4：发送图片

用 send_image 工具发送生成的 PNG：

```
send_image(cards/out/000.png)
```

可以附带一句简短说明（如卡牌名称、做了什么）。

## 规范语法速查（body 正文怎么写）

### 行动效果的规范句式

**启动效果**（➡️）：
```
➡️【行动成本】：【动作名】。效果描述。
```
例：`➡️横置铲子：【攻击】。你本次检定得到+2👊。造成+1伤害。`

**反应效果**（⚡）：
```
⚡【触发条件】，【行动成本】：效果描述。
```
例：`⚡在你回合期间，花费1资源：你本回合可以进行额外1次行动。(每回合仅限一次)`

**使用次数**：
```
使用(N类型)。
```
例：`使用(3充能)。` 或 `使用(2子弹)。` 补充写 `每轮开始时重新补满。`

### 常见属性加成写法

- `得到+2👊`（+2 战力）
- `得到+1📚`（+1 智力）
- `获得🧠👊🦶`（获得三个属性图标）
- `造成1点伤害` / `造成+1伤害`
- `受到1点恐惧` / `治愈1点恐惧`
- `获得2资源` / `花费1资源`
- `发现你所在地点的1个线索`

完整规范参考见同目录 `tag-reference.md`。

## 卡牌类型完整参考

以下是每种卡牌类型的完整字段说明和模板。**所有卡牌都有 name 和 body（body 可为空字符串），以下只列出各类型特有的字段。**

### 玩家卡（构筑卡组用的卡）

#### 支援卡（资产卡：武器、工具、盟友、法术等）

```json
{
  "type": "支援卡",
  "name": "战术铲",
  "class": "生存者",
  "cost": 3,
  "level": 0,
  "traits": ["道具", "工具", "武器", "近战"],
  "slots": "手部",
  "health": -1,
  "horror": -1,
  "body": "使用(3耐久)。\n➡️花费1耐久：【攻击】。你本次检定得到+1👊。造成+1伤害。",
  "language": "zh"
}
```
- `cost`：费用数字。正数=正常费用；`-1`=无费用（永久卡/天赋）；`-2`=X 费用。
- `traits`：特性数组（**不带句号**）。常见：道具、武器、近战、枪械、工具、科学、法术、才能、仪式、协作、遗物、乐器、守护、祝福、诅咒萦绕、违法、盟友、天赋。
- `slots`：槽位。取值：`手部`、`双手`、`法术`、`双法术`、`身体`、`盟友`、`附件`、`饰品`、`塔罗`、`空`（空图标槽位）。无槽位填 `null`。如有第二槽位可加 `slots2`。
- `health`/`horror`：非盟友类支援卡填 `-1`；盟友类填正数（如 health:2, horror:2）。

#### 事件卡

```json
{
  "type": "事件卡",
  "name": "心胜于物",
  "class": "探求者",
  "cost": 1,
  "level": 0,
  "traits": ["洞察"],
  "body": "快速。只能在你回合期间打出。\n直到本轮结束，你可以用你的📚代替你的👊和🦶。",
  "language": "zh"
}
```
- 字段同支援卡（cost/level/traits），但无 slots/health/horror。

#### 技能卡

```json
{
  "type": "技能卡",
  "name": "推理",
  "class": "探求者",
  "level": 0,
  "traits": ["精通"],
  "submit_icon": ["智力"],
  "body": "如果调查一个地点时本技能检定成功，额外发现该地点的1个线索。",
  "language": "zh"
}
```
- `submit_icon`：**技能卡特有**。投入图标数组，元素只能是：`意志`、`智力`、`战力`、`敏捷`、`狂野`。可重复（如 `["战力","战力","狂野"]` 表示拳拳？）。简称转换：脑→意志、拳→战力、脚→敏捷、书→智力、?→狂野。
- 无 cost/slots。

#### 升级卡 / 定制卡（DIY 通用卡，最灵活）

```json
{
  "type": "升级卡",
  "name": "自定义卡牌",
  "class": "守护者",
  "body": "正文内容，用规范 emoji 和【】语法写。",
  "language": "zh"
}
```
- 只有 name + body + class。升级卡正文支持 `□` 方框标记升级选项（每个选项一行，`□` 数量=XP 档位）：`□ 【选项名。】 效果描述。`

#### 调查员卡（正面）

```json
{
  "type": "调查员",
  "name": "🏅\"倒霉蛋\"奥图尔",
  "class": "流浪者",
  "subtitle": "前科犯",
  "attribute": [2, 3, 3, 4],
  "health": 8,
  "horror": 6,
  "traits": ["罪犯"],
  "body": "⚡在你回合期间，花费2资源：你本回合可以进行额外1次行动。(每回合仅限一次)\n⭐效果：+2。如果你成功，获得2资源。",
  "language": "zh"
}
```
- `subtitle`：副标题（调查员的职业/身份描述）。
- `attribute`：**四维数组** `[意志, 智力, 战力, 敏捷]`，每个 1-5 的整数。如 `[2,3,3,4]`。
- `health`/`horror`：调查员的生理伤害/精神恐惧承受上限（正数）。
- `body`：调查员能力。常用 `⚡`（反应能力）+ `⭐效果：+N。附加效果`（技能投入时的加成）。
- 独特调查员 name 前可加 `🏅`。

#### 调查员卡背

```json
{
  "type": "调查员卡背",
  "name": "🏅佐伊·萨马拉斯",
  "subtitle": "主厨",
  "card_back": {
    "other": "【牌库卡牌张数：】30。\n【牌库构建选项：】守护者卡牌(🛡️)等级0-5，中立卡牌等级0-5，所有其他职阶的卡牌(🔍、🚶、🧘和/或🏕️)等级0最多5张。\n【牌库构建需求】(不计入卡牌张数)：佐伊的十字架、击退邪恶、1张随机基础弱点。",
    "story": "调查员的背景故事..."
  },
  "language": "zh"
}
```
- `card_back`：**调查员卡背特有**的对象，包含：
  - `other`：牌库构建规则。用【】标记每段：`【牌库卡牌张数：】30。`、`【牌库构建选项：】...`、`【牌库构建需求】(不计入卡牌张数)：...`。额外规则用 `【额外冒险设置：】`。
  - `story`：调查员背景故事（风味文字）。
- name 通常和正面调查员同名。

### 遭遇卡（剧本里的卡）

#### 敌人卡

```json
{
  "type": "敌人卡",
  "name": "🏅塞拉斯·毕晓普",
  "class": "遭遇",
  "traits": ["怪物", "异形", "精英"],
  "enemy_damage": 2,
  "enemy_damage_horror": 2,
  "attack": "3",
  "evade": "7",
  "enemy_health": "6<调查员>",
  "victory": 2,
  "body": "庞大。\n塞拉斯·毕晓普不能进行趁乱攻击。",
  "language": "zh"
}
```
- `class`：遭遇卡填 `"遭遇"`。
- `enemy_damage`：敌人造成的生理伤害（整数）。
- `enemy_damage_horror`：敌人造成的精神恐惧（整数）。
- `attack`：攻击值（**字符串型**），如 `"3"`、`"X"`、`"?"`。
- `evade`：躲避值（**字符串型**）。
- `enemy_health`：敌人生命值（**字符串型**）。可为数字字符串 `"6"`，或 `"X"`、`"?"`，或按调查员数缩放 `"6<调查员>"`（表示6×调查员数）。
- `victory`：胜利点数（整数或 null）。

#### 地点卡

```json
{
  "type": "地点卡",
  "name": "走廊",
  "location_type": "已揭示",
  "traits": [],
  "shroud": "1",
  "clues": "0<调查员>",
  "location_icon": "红方",
  "location_link": ["蓝三角", "红十", "绿菱"],
  "victory": null,
  "body": "",
  "language": "zh"
}
```
- `location_type`：**必填**。`已揭示` 或 `未揭示`。
- `shroud`：险峻值（**字符串型**）。**仅已揭示面填**，如 `"2"`、`"?"`、`"X"`。未揭示面不填。
- `clues`：线索值（**字符串型**）。**仅已揭示面填**。可为 `"2"` 或按调查员数缩放 `"2<调查员>"`。
- `location_icon`：地点图标标识。取值：`绿菱`、`暗红漏斗`、`橙心`、`浅褐水滴`、`深紫星`、`深绿斜二`、`深蓝T`、`紫月`、`红十`、`红方`、`蓝三角`、`褐扭`、`青花`、`黄圆`。
- `location_link`：连接的地点图标数组（元素同上）。
- 未揭示面地点卡：`location_type: "未揭示"`，不填 shroud/clues。

#### 诡计卡

```json
{
  "type": "诡计卡",
  "name": "引起怀疑",
  "class": "遭遇",
  "traits": [],
  "body": "【显现】 - 在你所在地点的每个{罪犯}敌人上放置1个毁灭标记。如果未因本效果放置毁灭标记，失去2资源。",
  "language": "zh"
}
```
- `class`：填 `"遭遇"`（遭遇诡计）或 `"弱点"`（玩家弱点诡计）。
- `body`：通常以 `【显现】 - 效果` 开头。

#### 场景卡（Act）

```json
{
  "type": "场景卡",
  "name": "被困于此",
  "serial_number": "1a",
  "threshold": "2<调查员>",
  "body": "",
  "language": "zh"
}
```
- `serial_number`：场景编号（如 `"1a"`、`"2b"`）。字母 a=正面，b=背面。
- `threshold`：推进阈值（**字符串型**），如 `"3<调查员>"`（3×调查员数的线索）或 `"7"`。

#### 密谋卡（Agenda）

```json
{
  "type": "密谋卡",
  "name": "食尸鬼崛起",
  "serial_number": "2a",
  "threshold": "7",
  "body": "",
  "language": "zh"
}
```
- `serial_number`：密谋编号（如 `"1a"`、`"2b"`）。
- `threshold`：毁灭推进阈值（**字符串型**），如 `"7"`。

#### 故事卡

```json
{
  "type": "故事卡",
  "name": "故事标题",
  "body": "故事正文...",
  "language": "zh"
}
```
- 只有 name + body。

### 通用字段说明

| 字段 | 类型 | 适用 | 说明 |
|---|---|---|---|
| `type` | string | 所有 | 卡牌类型（见上方各类型） |
| `name` | string | 所有 | 卡牌标题 |
| `class` | string | 玩家卡/遭遇卡 | 职阶：守护者/探求者/流浪者/潜修者/生存者/中立/多职阶/遭遇/弱点 |
| `subclass` | string[] | 多职阶卡 | 当 class="多职阶"时，填包含的职阶（最多2个） |
| `cost` | number | 支援卡/事件卡 | 费用。正数=费用；-1=无费用；-2=X 费用 |
| `level` | number | 玩家卡 | 等级 0-5。-1=无等级 |
| `traits` | string[] | 大多数 | 特性数组（不带句号） |
| `body` | string | 所有 | 效果正文（emoji+【】语法） |
| `flavor` | string? | 可选 | 风味文字（背景故事/台词） |
| `language` | string | 所有 | `zh`（中文）、`en`、`zh-CHT` |
| `victory` | number? | 敌人/地点 | 胜利点数（null=无） |
| `picture_base64` | string? | 可选 | base64 图片（可带 `data:image/...` 前缀） |
| `picture_path` | string? | 可选 | 工作目录内图片路径（`@`开头） |
| `weakness_type` | string? | 弱点卡 | class="弱点"时：`弱点`（随机弱点）或 `基础弱点` |

## 图片处理

- 升级卡（DIY卡）：不需要图片，用固定的模板卡框。
- 其它卡类型：若需要自定义插画，用 `picture_path`（工作目录内的图片相对路径，以 `@` 开头）。
- **用户发来的图片**：当用户在群里发图片时，图片会自动下载到工作目录的 `inbox/` 文件夹。消息文本里会标注 `[用户发来一张图片：inbox/xxx.jpg]`。你直接在 .card 里写 `"picture_path": "@inbox/xxx.jpg"` 即可将该图作为卡牌底图。
- **沙箱断网**：你无法下载网上的图片 URL。若用户只给了 URL 没发图，请用户直接在群里发图片。

## 常见问题

- **渲染失败**：检查 JSON 是否合法。`body` 里有引号要用 `\"` 转义。
- **文件名错误**：必须是 `NNN*.card`（前3位数字）。不要用 `my-card.card`，要用 `000.card`。
- **图标没渲染**：确认用的是 emoji（👊📚🧠🦶）而不是尖括号标签（`<拳>` 是错的）。
- **正文显示不全**：升级卡的正文区域很大，但如果文字太多会被裁剪。精简描述。
