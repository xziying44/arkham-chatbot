# DIY 卡牌助手

两种模式：**生成卡图** 和 **纯文本效果编写**。根据用户意图选择。

## 模式判断（第一步永远是判断"用户给全了吗"）

收到任何制卡请求，**先判断用户输入的完整度**，这决定了要不要加载额外的数值/语法技能：

| 输入完整度 | 判断标志 | 处理方式 |
|---|---|---|
| **A. 完整输入** | 名称、职阶、数值（属性/血san 或 cost/等级）、正文效果、卡背信息（牌组/构筑等）**都已给齐**，且正文用了规范术语 | **直接渲染流程**：只加载本技能(diy-card)，**不要加载** arkham-card-numbers，**不要加载** card-text-lint，**不要跑** balance_check.py。用用户原文写 .card → 预览 → 确认 → 渲染 |
| **B. 不完整/要设计** | 只给了模糊想法（「做张很强的武器卡」）、数值没给、或明确要你帮忙（「帮我配平」「这个效果怎么写」） | **完整设计流程**：按需加载 arkham-card-numbers（配数值）和/或 card-text-lint（校准大白话），跑校验 |
| **C. 模糊** | 拿不准算不算完整 | **先问用户**：「你是想让我直接渲染这张卡，还是要帮你调整数值/语法？」不要自己猜着加载技能 |

**判断"完整"的标准**：用户给的数值和正文是否够用来直接写 .card 文件。如果数值已定（哪怕你个人觉得偏强/偏弱，但用户没问）、正文已用规范术语（"补给阶段""检定""反应""抽取""弃掉"等），就算完整。**不要替用户操心数值合不合理——那是用户的事，除非用户明确要求你帮忙配平。**

### 意图模式

| 用户说的 | 走哪个模式 |
|---|---|
| 「帮我做张卡」「生成卡图」「设计一张XX卡」 | **生成卡图**（按上面的完整度判断走 A 或 B） |
| 「帮我写个效果」「这个效果怎么写」「翻译成官方用语」 | **纯文本效果编写**（不生成图，但最后可问是否要生成） |
| 不确定 | 先按纯文本走，写完效果后问「要不要帮你生成卡图？」 |

## 模式 A：生成卡图（完整流程）

### Step 1：判断完整度 + 只加载必要的技能

**先按上面的"模式判断"表判断输入属于 A（完整）/ B（不完整）/ C（模糊）。**

- **A（完整输入）**：只加载 `load_skill("diy-card", { references: ["references/card-types.md"] })` 拿到字段模板。**跳过本步骤后面的数值/语法技能加载**，直接进 Step 3 写 .card。**不要跑 balance_check.py。** A 流程的完整路径是：**Step 3 写 .card → Step 4 发预览等用户确认 → （用户确认后）Step 5 渲染发图**。这是同一次任务里的连续步骤，发完预览不算结束——你要带着"等用户回确认，回来就渲染"的状态。
- **B（不完整/要设计）**：加载 `load_skill("diy-card", { references: ["references/card-types.md"] })`，然后**按需**加载：
  - 用户要配平数值 / 没给数值 / 问数值合理性 → `load_skill("arkham-card-numbers", { references: ["references/investigators.md"] })`（调查员）/ `references/assets.md`（支援卡）
  - 用户用大白话描述效果 → `load_skill("card-text-lint")` 校准
  - **不要默认两个都加载**——只在真的需要时加载对应那个
- **C（模糊）**：用 send_message 问用户意图，问清楚再走 A 或 B。

必须收集的信息（A/B 都要）：
- **卡牌类型**：若用户没指定，用 ask_user 问（支援卡/事件卡/技能卡/调查员/敌人/地点/升级卡）
- **名称**（name）
- **正文**（body）：效果描述
- **职业**（class）：守护者/探求者/流浪者/潜修者/生存者/中立

**带 references 参数能省掉后续 read 往返**——一次 load_skill 把 SKILL.md 和参考文件全文都拿回来。

### Step 2：配平数值（仅 B 流程需要）

仅当输入不完整、你在自由设计数值时，按 arkham-card-numbers 技能的「数值速记」把数值放进官方预算。超标准线的效果配显性代价。
**A 流程（用户已给全数值）跳过这一步——用用户给的数值原值，不自作主张调整或校验。**

### Step 3：写 .card（+ 数值校验，仅 B 流程）

用 write 工具写 JSON 到 `cards/in/000.card`（文件名前3位必须是数字）。**A 流程和 B 流程都要写**——.card 是渲染的前提，没它后面没法出图。

**数值校验只在 B 流程（自由设计）时做**：写完后跑
```bash
python3 skills/arkham-card-numbers/scripts/balance_check.py "$(cat cards/in/000.card)"
```
error 必须清零，warning 需给出补偿理由。

**A 流程（用户已给全数值）不要跑 balance_check**——直接写 .card 进下一步。用户没要求校验，跑了只会让你忍不住对用户已定的数值指手画脚。

### Step 4：发送文本预览给用户确认

**先不要渲染卡图！** 渲染和发送都比较慢（3-10秒），用户等太久会觉得卡住了。
用 send_message 把卡牌信息整理成文本预览发给用户：

```
帮你整理好了，请确认：

**【卡名】**（职阶 · 特性）费用/等级
正文效果（规范语法）
数值（生命/理智/攻击等）

确认无误就帮你生成卡图，要改随时说。
```

等用户回复「可以」「没问题」「确认」后再渲染。用户要改就调整后再次确认。

**A 流程特别注意——不要追问用户没给的可选字段**：
- 用户没给的字段（副标题、背景故事、画作、版权等）**直接留空或用默认值**，不要发一堆问题让用户补。
- 用户在第一条消息里给的，就是他想要这个卡的全部内容。预览只是为了让他核对"你有没有抄错/格式化对不对"，不是让他补充内容。
- 预览消息里**只问一句话**：「确认就帮你出图，要改随时说。」不要再列「还需要你提供：副标题/背景故事/…」清单。
- 只在用户给的**必填信息有硬缺失**（比如调查员没给技能数值、支援卡没给 cost）时才追问，且追问要精确到那一个字段。

### Step 5：渲染 + 发送图片

```bash
mkdir -p cards/out
.arkham/bin/arkham-cli render \
  --corpus cards/in \
  --assets .arkham/assets \
  --workspace . \
  --out cards/out
```

- `--workspace .` **必须带**：解析 picture_path 的相对路径
- 输出 `cards/out/000.png`，看 `[OK ]` / `[ERR]` 判断成功
- 用 send_image 发送

## 模式 B：纯文本效果编写

用户只想把大白话描述翻译成官方规范语法，不需要生成卡图。

### Step 1：理解用户意图

用户描述效果（如「3费，装上去后获得+1拳，攻击消耗耐久度，用3次就坏了」）。

### Step 2：校准语法

调 `load_skill("card-text-lint")` 加载语法校准技能，按官方规范重写。

### Step 3：发送规范文本

用 send_message 把校准后的效果发给用户：

```
帮你翻译成官方规范语法：

使用(3耐久)。
你得到+1👊。
➡️花费1耐久：【攻击】。你本次检定得到+1👊。造成+1伤害。
当此卡上没有耐久时，弃掉此卡。

要调整随时说。
```

### Step 4：问是否生成卡图

用户确认效果后，可以问一句：「要不要帮你把这张卡生成卡图？」
用户说要就切到模式 A 的 Step 2 继续。说不要就结束。

## 图标语法速查（两种模式通用）

body 里必须用 emoji，不用尖括号标签：

| 含义 | emoji | | 含义 | emoji |
|---|---|---|---|---|
| 意志 | 🧠 | | 战斗 | 👊 |
| 智识 | 📚 | | 敏捷 | 🦶 |
| 行动 | ➡️ | | 快速/反应 | ⚡ |
| 回合结束 | ⭕ | | 独特 | 🏅 |

常用写法：`得到+2👊`、`造成1点伤害`、`发现1个线索`、`获得2资源`、`【攻击】`、`【调查】`。
被动触发（「在…后」「当…时」）用 ⭕ 反应图标，不要用 ⚡。
完整标签参考见 `references/tag-reference.md`。

## 图片处理

- 升级卡（DIY卡）：不需要图片，用固定模板卡框
- 其它卡类型用用户提供的底图：用户发图片时自动存到 `inbox/`，在 .card 里写 `"picture_path": "inbox/xxx.jpg"`（**不加 @ 前缀**）
- 沙箱断网，无法下载网上图片 URL

## 常见错误提醒

- 调查员卡背的 `class` 必须和正面一致（漏填会用中立卡框）
- 被动触发效果用 ⭕ 不用 ⚡
- 渲染命令必须带 `--workspace .`
- picture_path 不加 `@` 前缀
